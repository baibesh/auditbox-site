Видео: одна минута

1. Установка

На сервере Linux одна команда. Вопросов она не задаёт.

curl -fsSL https://baibesh.github.io/auditbox-site/install.sh | sudo sh

Что она делает сама:

  • скачивает программу (один файл) и сверяет контрольную сумму;
  • ставит службу auditbox с автозапуском;
  • поднимает базу: ставит PostgreSQL, если его нет, или заводит отдельную базу в уже стоящем. Чужие базы не трогает;
  • выбирает свободный порт и запускает службу;
  • печатает ссылку, по которой установка завершается в браузере.

Если у сервера есть имя, укажите его сразу, и HTTPS настроится в той же команде:

curl -fsSL https://baibesh.github.io/auditbox-site/install.sh | sudo sh -s -- --domain audit.example.kz

Нужен Linux с systemd. PostgreSQL, nginx и сертификат команда ставит сама на Debian и Ubuntu.

2. Первый вход

Откройте ссылку, которую напечатала команда. В браузере мастер из двух шагов:

  1. Администратор. Логин и пароль первого пользователя. Пароль можно сгенерировать кнопкой.
  2. Первая система. Название того, что будет присылать изменения, например CRM. В ответ мастер показывает ключ системы и две готовые строки для её настроек.

Ключ показывается один раз. Ссылка одноразовая: после создания администратора она перестаёт работать. Новая ссылка, пока администратор не создан:

sudo auditbox setup-link

Без имени сервера AuditBox слушает только сам сервер. Тогда команда печатает строку туннеля, которая запускается на вашем компьютере, и адрес вида http://localhost:8190/setup/….

3. Как встроить код

Ваша система сообщает AuditBox о каждом сохранении настроек одним запросом. Считать, что именно изменилось, ей не нужно: она отправляет состояние до и после, а AuditBox сам сравнивает их, пишет по строке на каждый изменённый параметр и скрывает секреты.

Три шага

  1. Положите адрес и ключ в настройки системы. Мастер выдаёт их готовыми строками: 
    AUDITBOX_URL=https://audit.example.kz
AUDITBOX_TOKEN=abx_…
  2. Найдите место, где система сохраняет настройки. Обычно это одна функция: «сохранить кампанию». Перед сохранением запомните прежнее состояние, после сохранения возьмите новое.
  3. Отправьте оба состояния в AuditBox вместе с тем, кто это сделал.

Запрос

curl -X POST "$AUDITBOX_URL/events" \
  -H "Authorization: Bearer $AUDITBOX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "event_id": "5b1f6c1e-7d0a-4f0e-9a43-2f6a0c1d8e11",
    "operation_id": "5b1f6c1e-7d0a-4f0e-9a43-2f6a0c1d8e11",
    "occurred_at": "2026-11-21T08:14:05Z",
    "entity_type": "campaign.sms",
    "entity_id": "12345",
    "action": "update",
    "actor": { "id": "u-77", "type": "user", "display": "a.ivanov" },
    "reason": "Перенос рассылки на вечер",
    "before": { "status": "active", "schedule": { "start_time": "09:00" } },
    "after":  { "status": "active", "schedule": { "start_time": "21:00" } }
  }'
ПолеЧто в нём
event_idУникальный номер события (UUID). Повтор с тем же номером второй раз не записывается.
operation_idНомер операции (UUID). Одинаковый у событий одного действия, например массовой правки; иначе равен event_id.
occurred_atКогда произошло изменение, в UTC.
entity_type, entity_idЧто изменили: тип объекта, как он задан в параметрах, и его номер.
actioncreate, update или delete.
actorКто изменил: id, type (user, system или api_token) и имя для показа.
reasonПричина, если система её знает. Необязательно.
before, afterОбъект целиком до и после. При создании нет before, при удалении нет after.

В коде

Node.js:

async function audit({ type, id, action, actor, before, after, reason }) {
  const eventId = crypto.randomUUID();
  const response = await fetch(process.env.AUDITBOX_URL + "/events", {
    method: "POST",
    headers: {
      Authorization: "Bearer " + process.env.AUDITBOX_TOKEN,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      event_id: eventId, operation_id: eventId,
      occurred_at: new Date().toISOString(),
      entity_type: type, entity_id: String(id), action, actor, reason, before, after,
    }),
  });
  if (!response.ok) throw new Error("AuditBox: " + response.status);
}

// там, где сохраняется кампания
const before = await campaigns.get(id);
const after = await campaigns.update(id, changes);
await audit({ type: "campaign.sms", id, action: "update", before, after,
  actor: { id: user.id, type: "user", display: user.login } });

Python:

import os, uuid, datetime, requests

def audit(type, id, action, actor, before=None, after=None, reason=None):
    event_id = str(uuid.uuid4())
    response = requests.post(
        os.environ["AUDITBOX_URL"] + "/events",
        headers={"Authorization": "Bearer " + os.environ["AUDITBOX_TOKEN"]},
        json={
            "event_id": event_id, "operation_id": event_id,
            "occurred_at": datetime.datetime.now(datetime.timezone.utc).isoformat(),
            "entity_type": type, "entity_id": str(id), "action": action,
            "actor": actor, "reason": reason, "before": before, "after": after,
        },
        timeout=5,
    )
    response.raise_for_status()

PHP:

function audit(string $type, string $id, string $action, array $actor, ?array $before, ?array $after): void {
    $eventId = bin2hex(random_bytes(16));
    $eventId = vsprintf('%s%s-%s-%s-%s-%s%s%s', str_split($eventId, 4));
    $ch = curl_init(getenv('AUDITBOX_URL') . '/events');
    curl_setopt_array($ch, [
        CURLOPT_POST => true,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_TIMEOUT => 5,
        CURLOPT_HTTPHEADER => [
            'Authorization: Bearer ' . getenv('AUDITBOX_TOKEN'),
            'Content-Type: application/json',
        ],
        CURLOPT_POSTFIELDS => json_encode([
            'event_id' => $eventId, 'operation_id' => $eventId,
            'occurred_at' => gmdate('Y-m-d\TH:i:s\Z'),
            'entity_type' => $type, 'entity_id' => $id, 'action' => $action,
            'actor' => $actor, 'before' => $before, 'after' => $after,
        ]),
    ]);
    curl_exec($ch);
    if (curl_getinfo($ch, CURLINFO_HTTP_CODE) >= 300) throw new RuntimeException('AuditBox refused the event');
}

Чтобы ни одно изменение не потерялось

Если AuditBox в момент сохранения недоступен, событие не должно пропасть. Надёжная схема такая:

  • в той же транзакции, что и само сохранение, система кладёт событие в свою таблицу-очередь;
  • фоновая задача отправляет события из очереди и удаляет их после ответа 201 или 200;
  • повторная отправка безопасна: по event_id AuditBox узнаёт дубль.

Почему событие не записалось, видно в админке: Настройки → Приём. Там каждый запрос и шаг, на котором он остановился.

4. Параметры: что попадает в журнал

В журнал пишутся не все поля объекта, а только те, что перечислены в параметрах. Настраивается это в админке: Настройки → Параметры → Изменить. Изменение действует сразу, перезапуск не нужен.

У каждого параметра четыре свойства:

СвойствоЧто этоПример
НазваниеКак параметр подписан в журнале.Время начала
Поле в данныхГде значение лежит в before и after. Вложенность через точку.schedule.start_time
ГруппаЗаголовок, под которым параметр показан. Необязательно.Расписание
СекретЗначение не записывается, остаётся только факт изменения.ключ провайдера

Как поле в данных соответствует тому, что присылает система:

"after": {
  "status": "paused",                       →  status
  "schedule": { "start_time": "21:00" },    →  schedule.start_time
  "limits":   { "per_day": 20000 },         →  limits.per_day
  "provider": { "api_key": "…" }            →  provider.api_key   (секрет)
}

Тип объекта в параметрах должен совпадать с entity_type в событии, например campaign.sms. Событие с типом, которого нет в параметрах, AuditBox отклонит.

Если убрать параметр, он перестанет записываться, а уже записанное останется. Пометка «секрет» скрывает значения с этого момента, а не в прошлых записях.

5. Если систему менять нельзя

Бывает, что система умеет только отдать свои данные как есть, например строку из таблицы изменений. Тогда она шлёт их на отдельный адрес, а короткий скрипт в AuditBox переводит их в событие. Скрипт задаётся в админке: Настройки → Источники → меню системы → Преобразование входа.

function transform(input) {
  if (input.tbl !== "campaigns") return null;   // не кампания: пропустить

  return {
    event_id: input.id,
    operation_id: input.id,
    occurred_at: input.ts,
    entity_type: "campaign.sms",
    entity_id: String(input.pk),
    action: "update",
    actor: { id: input.usr, type: "user" },
    before: input.old,
    after: input.new,
  };
}

Там же есть консоль проверки: вставляете пример данных и сразу видите, какие строки появятся в журнале. В журнал при проверке ничего не пишется. Данные система отправляет на POST /intake/<идентификатор системы> с тем же ключом.

6. Адрес и HTTPS

Сразу после установки AuditBox слушает только сам сервер. Открыть его под именем с HTTPS можно одной командой: она получает сертификат и включает сайт в nginx.

sudo auditbox https audit.example.kz

Имя должно уже указывать на этот сервер. Закрыть обратно:

sudo auditbox https off

7. Обновление и команды

Обновление — та же команда, что при установке. На сервере, где AuditBox уже стоит, она заменяет программу, обновляет таблицы и перезапускает службу.

ЧтоКоманда
Новая ссылка для завершения установкиsudo auditbox setup-link
Журнал службыjournalctl -u auditbox -n 100
Цела ли цепочка журналаsudo auditbox --config /etc/auditbox/auditbox.toml verify
Новый администратор, если пароль утерянsudo auditbox --config /etc/auditbox/auditbox.toml user create <логин> --role admin
Удалить программу (настройки и база остаются)sudo auditbox uninstall

Резервная копия AuditBox — это копия его базы: pg_dump auditbox. Файлов данных у программы нет.
